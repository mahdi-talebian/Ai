# ردِّ صدا ۱٫۳٫۳ — نت‌های کشیده با نوارِ ضخیم طلایی

## چه چیزی عوض شد؟

تا پیش از این، هر نُت روی نمودار فقط **یک نقطه** بود؛ نُتی که دو ثانیه کشیده
می‌شد هم مثل نُتِ ۰٫۲ ثانیه‌ای دیده می‌شد. حالا — دقیقاً مثل عکس‌هایی که
فرستادی — هر نُتی که **امتداد** دارد، نوارِ گرد و ضخیمِ طلایی می‌گیرد:

- نوار در **ارتفاعِ همان نُت** و به **طولِ همان نُت** کشیده می‌شود.
- **ضخامتش با طولِ نُت** تعیین می‌شود: از ~۵٫۴px برای نُتِ کوتاه تا ~۱۶px برای
  نُتِ ۴ ثانیه‌ای و بیشتر (در مقیاس ۱۲۸۰px؛ در ۱۰۸۰p به‌نسبت بزرگ‌تر).
- در **حینِ پخش رشد می‌کند**: نوارِ نُتِ در حالِ اجرا فقط تا خطِ پخش کشیده
  می‌شود، پس امتدادِ نُت را زنده می‌بینی.
- نُت‌های **آینده** (ناخوانده) نوارِ نازک و محو دارند، نه کپسولِ طلایی — طلایی
  مالِ چیزی است که واقعاً خوانده شده.
- نُتِ کوتاه (زیر **۰٫۳۴s**) همچنان همان نقطهٔ ریز است (نتِ تزیینی نوار نمی‌گیرد).

همهٔ این‌ها در **یک** فایل است (`web/trace_style.js`)، پس اپ، تصویر تحلیل و
ویدیو عیناً یک چیز را نشان می‌دهند.

## تست‌ها

`trace_style_test` از ۱۳ به **۲۳** بررسی رسید؛ بررسی‌های تازه با یک بومِ
ضبط‌کننده، خودِ رسم را می‌سنجند (نه فقط اعداد را):

| بررسی | نتیجه |
|---|---|
| نت‌های کشیده واقعاً نوارِ ضخیم می‌گیرند | ✅ ۶ stroke افقی |
| نوار در ارتفاعِ دقیقِ همان نت است | ✅ y(C4)=448 · y(D4)=367 |
| ضخامت از طولِ نت می‌آید | ✅ ۲۴٫۷px برای نتِ ۲٫۶s (k≈۱٫۸) |
| نتِ طولانی‌تر ⇒ نوار کلفت‌تر | ✅ ۶٫۷ / ۱۳٫۱ / ۱۶px |
| نوارِ آینده نازک‌تر از کپسولِ طلایی | ✅ ۱۴٫۸ در برابر ۲۴٫۷px |
| طول نوار ≈ تمامِ مدتِ نت | ✅ ۵۵→۳۴۵ در برابر ۴۳→۳۵۷ |
| نوار با زمان رشد می‌کند | ✅ ۱۳۳px در t=1.2s → ۲۹۰px در پایانِ نت |
| نتِ کوتاه نوار نمی‌گیرد (نقطه می‌ماند) | ✅ ۰ نوار · ۴ نقطه |
| نوارِ نتِ بیرونِ پنجرهٔ زوم رسم نمی‌شود | ✅ |

بقیهٔ مجموعه‌ها هم سبز: apk_test **۲۵** · video_fast **۲۱** · strict **۲۵** ·
live **۳۳** · parallel **۹** · render · video · decode · native **۱۱** · page.
