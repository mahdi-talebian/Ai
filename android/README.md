# 📱 اپ اندروید «ردِّ صدا» — ساخت و نصب

این پوشه، همان رابط وب (`web/`) را به یک APK قابل نصب تبدیل می‌کند؛ **بدون
Gradle، بدون Android Studio و بدون Android SDK کامل**.

```
release/radde-seda-1.3.7.apk      ← فایل آمادهٔ نصب (versionCode 17)
```

> **از نسخهٔ ۱٫۱٫۰ به بعد اپ به هیچ سروری وصل نمی‌شود.** موتور تحلیل
> (`web/engine.js`) و لایهٔ آفلاین (`web/offline.js`) داخل بستهٔ اپ هستند و
> همهٔ کارها — رمزگشایی فایل، تحلیل، نمودار، ویدیو، گزارش و اجرای زنده — روی
> همان گوشی انجام می‌شود. نه آدرس سروری لازم است، نه اینترنت، نه ffmpeg.

---

## نصب روی گوشی

1. فایل `release/radde-seda-1.3.7.apk` را روی گوشی کپی کنید (کابل، تلگرام
   «Saved Messages»، Google Drive… هر چیزی).
2. روی فایل بزنید؛ اگر پیام «نصب از منابع نامشخص» آمد، برای همین برنامه
   اجازه بدهید.
3. برای جایگزین‌کردن نسخهٔ قبلی، باید همان کلید امضا (`android/keystore`) باشد
   — پس این پوشه را نگه دارید.

اندروید ۷ (API 24) و بالاتر.

---

## اولین اجرا: هیچ تنظیمی لازم نیست

اپ را باز کنید؛ فقط همین. صفحه از حافظهٔ خود گوشی باز می‌شود
(`https://appassets.local`) و همهٔ پردازش همان‌جا انجام می‌شود. نشان سبز
**«🔒 ۱۰۰٪ روی همین دستگاه — بدون اینترنت، بدون سرور»** بالای صفحه یعنی
همین حالت فعال است. دکمهٔ «⚙ سرور» هم وجود ندارد.

برای اطمینان می‌توانید حالت هواپیما را روشن کنید و همهٔ مسیرها را امتحان کنید:
انتخاب فایل → تحلیل → PNG → ویدیو → گزارش → پخش تعاملی → اجرای زنده.

### سرعت: تحلیل موازی داخل اپ

از ۱٫۲٫۰ موتور تحلیل بین چند Web Worker پخش می‌شود (تا ۴ کارگر، بر اساس
`navigator.hardwareConcurrency`). در WebView هم کار می‌کند چون فایل‌ها از
مبدأ داخلی `appassets.local` سرو می‌شوند و `worker.js` هم از همان‌جا
بارگذاری می‌شود. اگر WebView قدیمی باشد و Worker را نپذیرد، موتور **بی‌صدا**
همان مسیر تک‌رشته‌ای را اجرا می‌کند؛ نتیجه یکسان است و فقط سرعت فرق می‌کند.
نشان «⚡ N هسته» کنار نوار پیشرفت نشان می‌دهد کدام مسیر فعال است.

### اگر عمداً نسخهٔ سروری می‌خواهید (اختیاری)

```bash
DEFAULT_API=https://your-server.example APP_VERSION=1.3.0 bash android/build_apk.sh
```

این مقدار داخل `BuildConfig.DEFAULT_API` جای می‌گیرد. در نسخهٔ وب معادلش این است:

```
?engine=server&api=https://your-server.example
```

> پیشنهاد: https (با http هم آپلود/تحلیل کار می‌کند، ولی «اجرای زندهٔ سروری»
> که از WebSocket استفاده می‌کند به https نیاز دارد). در حالت آفلاین این
> محدودیت وجود ندارد.

## چه چیزهایی در اپ کار می‌کند؟

| قابلیت | مسیر در اپ |
|---|---|
| انتخاب فایل صوتی/ویدیو از گوشی | `onShowFileChooser` → انتخاب‌گر فایل اندروید |
| آپلود + تحلیل + نتایج | موتور محلی داخل اپ (`web/engine.js`) — بدون شبکه |
| ذخیرهٔ فایل اصلی / تصویر / گزارش JSON | MediaStore → `Downloads/` و `Pictures/` |
| ساخت ویدیوی ردِّ صدا | دکمهٔ 🎬 — canvas + MediaRecorder داخل اپ (بدون ffmpeg)؛ نوار لغزان ۱۵ ثانیه‌ای با نقطهٔ وسط |
| فیلتر نت‌ها در تصویر/ویدیو | فقط نت‌های واقعی؛ پرش‌های اکتاوی و نویزِ بی‌نت رسم نمی‌شوند |
| ذخیرهٔ ویدیو در گالری | بلاب محلی → MediaStore `Movies/` (RELATIVE_PATH با اسلش پایانی، پسوند هم‌خوان با نوع فایل، نتیجه به صفحه برمی‌گردد) |
| ذخیرهٔ تصویر تحلیل در گالری | بلاب PNG → MediaStore `Pictures/` |
| ذخیرهٔ ویدیو در پوشهٔ دانلودها | DownloadManager → `Downloads/` با اعلان پیشرفت |
| اجرا با ضبط (تنها حالت) | میکروفون WebView (`onPermissionRequest`) + تحلیل محلی (بدون WebSocket)؛ در سکوت هیچ نتی ساخته نمی‌شود |
| حذف جلسه‌ها | 🗑 برای هر ضبط + «حذف همه»، هر دو با تأیید دو مرحله‌ای |
| ذخیرهٔ صدای ضبط‌شده (WAV) و گزارش هر ضبط | پل بومی، ارسال تکه‌تکهٔ base64 (پایدار برای فایل‌های چند مگابایتی) |
| نمونهٔ آزمایشی | همان فایل `demo_bayati.wav` از assets |

نکته‌ها:

* WebView خودش «blob» را دانلود نمی‌کند؛ برای همین `web/native.js` مسیر
  ذخیره را به کد بومی می‌سپارد. در مرورگر این فایل **بی‌اثر** است و رفتار
  نسخهٔ وب دقیقاً همان قبلی می‌ماند.
* Service Worker (PWA) در اپ لازم نیست؛ ثبتش بی‌صدا نادیده گرفته می‌شود.
* **هیچ داده‌ای از گوشی بیرون نمی‌رود.** بهترین آزمون: حالت هواپیما.
* دسترسی‌ها: `RECORD_AUDIO`، `INTERNET` (فقط برای حالت سروری اختیاری؛ در حالت
  آفلاین استفاده نمی‌شود)، و فقط تا اندروید ۹
  `WRITE_EXTERNAL_STORAGE` (از اندروید ۱۰ به بعد MediaStore، بدون مجوز).

## ساخت مجدد APK

```bash
bash android/tools/fetch_toolchain.sh     # یک‌بار: java + aapt2 + d8 + apksigner + ecj
bash android/build_apk.sh                 # خروجی: release/radde-seda-<version>.apk
```

متغیرهای اختیاری:

```bash
VERSION_NAME=1.3.7 VERSION_CODE=17 APP_VERSION=1.3.7 bash android/build_apk.sh
ANDROID_TOOLS=/path/to/tools JAVA_HOME=/path/to/jdk bash android/build_apk.sh
```

زنجیرهٔ ابزار (همه از منابع عمومی، بدون Google Maven):

| ابزار | منبع |
|---|---|
| `java` (JRE) | بستهٔ پایتونی `jdk4py` (pypi) |
| `aapt2` (linux) | بستهٔ نُدِ `aaptjs3` (npm) |
| `android.jar` (API 34)، `d8.jar`، `apksigner.jar`، `ecj` | بستهٔ نُدِ `@drxiaozhi/minapk` (npm) |
| ترازبندی ۴ بایتی | `android/tools/zipalign.py` (پیاده‌سازی پایتونی `zipalign`) |

مراحل ساخت در `build_apk.sh`:

```
web/  →  android/assets/web/          (کپی خودکار؛ شامل engine.js · parallel.js · worker.js · offline.js)
res/  →  aapt2 compile + link         (منابع + مانیفست + assets)
java/ →  ecj (جایگزین javac) → d8     (classes.dex)
        → بستن در APK → zipalign.py → apksigner (v2+v3)
```

## ساختار

```
android/
  AndroidManifest.xml          مجوزها، مانیفست اپ
  build_apk.sh                 اسکریپت ساخت کامل
  tools/fetch_toolchain.sh     گرفتن ابزارها
  tools/zipalign.py            هم‌ترازی APK (پیش‌نیاز اندروید ۱۱+)
  java/ir/raddeseda/app/MainActivity.java
  res/                         آیکون‌ها، تم، رشته‌ها
  keystore/radde-seda.jks      کلید امضا (رمز: raddeseda / alias: raddeseda)
  assets/                      در زمان ساخت از web/ پر می‌شود (در گیت نیست)
```

> کلید امضا داخل مخزن است تا نسخه‌های بعدی روی همین اپ نصب شوند. اگر می‌خواهید
> اپ را جایی منتشر کنید، کلید تازه بسازید و `KS`/`KS_PASS` را در
> `build_apk.sh` عوض کنید.
