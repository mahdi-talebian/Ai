# 🎧 تحلیلگر هوشمند صوت و تلاوت قرآن

مجموعه‌ای از ابزارهای تحلیل صوتی، از تحلیل موسیقایی عمومی تا تحلیل تخصصی و
دقیق تلاوت قرآن با تشخیص مقام عربی، نمایش زنده روی پیانو، و مقایسه ملودیک
دو فراز.

## فهرست ابزارها

| ابزار | توضیح |
|---|---|
| `web/index.html` | اپ وب مستقل (بدون سرور) برای تحلیل موسیقی عمومی — آپلود/میکروفون، BPM، کلید |
| `python/audio_analyzer.py` | تحلیلگر موسیقی عمومی با `librosa` (BPM، کلید، MFCC، طیف) |
| `python/pitch_engine.py` | **هسته مشترک**: استخراج دقیق pitch با Praat + تبدیل نت + DTW |
| `python/quran_maqam_analyzer.py` | تحلیل دقیق تلاوت قرآن + تشخیص مقام عربی |
| `python/piano_visualizer.py` | نمایش زنده نت روی کلاویه پیانو (از فایل یا میکروفون) |
| `python/compare_recitations.py` | مقایسه ملودیک/ریتمیک دو فراز با DTW |

## نصب

```bash
cd python
pip install -r requirements.txt
```

برای نمایش صحیح فارسی در نمودارها، فونت Vazirmatn را در `~/.fonts/` قرار دهید:
```bash
mkdir -p ~/.fonts
curl -sL -o ~/.fonts/Vazirmatn-Regular.ttf \
  "https://github.com/rastikerdar/vazirmatn/raw/master/fonts/ttf/Vazirmatn-Regular.ttf"
```

برای `piano_visualizer.py` (پخش صدا/میکروفون)، کتابخانه سیستمی PortAudio هم لازم است:
```bash
sudo apt-get install -y portaudio19-dev libportaudio2
```

برای صادرات ویدیو (`--export-video`)، `ffmpeg` هم لازم است:
```bash
sudo apt-get install -y ffmpeg
```

## ۱. `pitch_engine.py` — هسته مشترک

این ماژول پایه همه ابزارهای دقیق پروژه است و مستقیماً اجرا نمی‌شود، بلکه
توسط بقیه فایل‌ها ایمپورت می‌شود. شامل:

- **استخراج F0 با موتور Praat** (نه librosa) — در آزمایش داخلی ما، Praat
  روی تن خالص و تن ربع‌پرده‌ای خطای **~۰ سنت** داشت در مقابل **~۷ سنت خطای
  pYIN** (که برای ربع‌پرده‌های ۵۰ سنتی مقام‌های عربی ناکافی است).
- تبدیل فرکانس ↔ نت پیانو ↔ موقعیت فیزیکی کلید (برای رسم روی کلاویه).
- فیلتر میانه (median filter) برای حذف نویز گذرا در لحظات حمله/فرود صدا.
- ادغام هوشمند قطعات مجاورِ هم‌پرده به یک نت واحد.
- پیاده‌سازی کامل **DTW** (Dynamic Time Warping) برای مقایسه ملودیک.

## ۲. `quran_maqam_analyzer.py` — تحلیل دقیق تلاوت + تشخیص مقام

```bash
python3 quran_maqam_analyzer.py recitation.mp3
python3 quran_maqam_analyzer.py recitation.wav --denoise
python3 quran_maqam_analyzer.py recitation.mp3 --output report.json --top-k 3
```

**قابلیت‌ها:**
- پاس دوگانه Praat برای دقت بالاتر + پاک‌سازی خطای جهش اکتاوی
- تفکیک نت‌به‌نت با زمان‌بندی دقیق
- تشخیص ویبراتو (نرخ Hz و دامنه سنت)
- تشخیص مقام از بین ۱۰ مقام اصلی (رست، بیات، حجاز، صبا، نهاوند، عجم، کرد،
  چهارگاه، سیکاه، نکریز) — بر پایه **استاندارد کنگره قاهره ۱۹۳۲**
- تشخیص سکوت‌ها/نفس‌ها و دامنه ملودیک (Ambitus)
- رسم ملوگراف (نمودار دقیق F0 + خطوط راهنمای مقام تشخیصی)

### 🧬 نظریهٔ عقد و جنس: زنجیرهٔ اجناس دقیق هر مقام (جدید)

هر مقام به‌جای «جدول مسط درجه‌ها» با منطق کلاسیک **عقد و جنس** مدل شده است
(مرجع: متن توصیف اجناس هر مقام در MaqamWorld + کنگرهٔ قاهره ۱۹۳۲):

- **جدول اجناس** (`JINSAT`): فرمول دقیق هر جنس «از یک نت واحد» با واحدهای
  سنتی آموزش تلاوت:
  - جنس راست: پردهٔ تام + سه‌ربع + سه‌ربع (۲۰۰+۱۵۰+۱۵۰)
  - جنس بیاتی: سه‌ربع + سه‌ربع + پردهٔ تام (۱۵۰+۱۵۰+۲۰۰)
  - جنس حجاز: نیم‌پرده + یک‌ونیم‌پرده + نیم‌پرده (۱۰۰+۳۰۰+۱۰۰)
  - جنس کرد: نیم‌پرده + پردهٔ تام + پردهٔ تام (۱۰۰+۲۰۰+۲۰۰)
  - جنس نهاوند: پردهٔ تام + نیم‌پرده + پردهٔ تام (۲۰۰+۱۰۰+۲۰۰)
  - جنس عجم/جهارکاه: پردهٔ تام + پردهٔ تام + نیم‌پرده (۲۰۰+۲۰۰+۱۰۰)
  - جنس صبا: سه‌ربع + سه‌ربع + نیم‌پرده (۱۵۰+۱۵۰+۱۰۰ — چهارم نیم‌بمل‌گرفته!)
  - جنس نکریز: پردهٔ تام + نیم‌پرده + یک‌ونیم‌پرده (۲۰۰+۱۰۰+۳۰۰ — گسترده)
  - جنس سیکاه: سه‌ربع + پردهٔ تام (۱۵۰+۲۰۰ — **ثلاثی**، گسترهٔ ۳۵۰ سنت)
- **زنجیرهٔ عقود هر مقام** (`jins_chain`): مثلاً صبا = جنس صبا روی عقد
  تونیک + جنس حجازِ هم‌پوشان روی درجهٔ ۳ + جنس عجم روی درجهٔ ۶؛ سیکاه =
  جنس ثلاثی سیکاه + راست بالایی روی درجهٔ ۳ + راست روی درجهٔ ۶. گام هر
  مقام **از زنجیرهٔ اجناس مشتق و با جدول اعتبارسنجی** می‌شود
  (`derive_scale_from_jins_chain`) تا نظریه و جدول هرگز از هم جدا نیفتند.
- **برچسب جنس هر نت**: هر نت در سولفژ می‌گوید متعلق به کدام جنس است و نُتِ
  چندم آن جنس است (`jins_fa`, `jins_position`) — مثلاً در بیاتی، درجهٔ ۵
  «نُت ۲ جنس نهاوند (روی درجهٔ ۴)» است.
- **گام‌به‌گام «از هر نت چقدر باید بروی»**: جدول درجات هر مقام فاصلهٔ هر
  درجه از قبلی را با واحدهای سنتی می‌گوید (`step_from_previous_fa`).
- **پیشینِ قرار (فرود)** برای تفکیک «هم‌ارزی چرخشی»: نت‌های کرد از درجهٔ ۴
  دقیقاً همان مجموعهٔ نهاوند از تونیک دیگر است و هیستوگرامِ محض آن‌ها را
  نمی‌تفکیکد؛ کاندیدهایی که تونیک‌شان نزدیک «قرار» (نتی که تلاوت روی آن
  می‌نشیند) باشد تا ۳۵٪ امتیاز بیشتر می‌گیرند — با این، دقت تست‌های
  سنتتیک (آغاز از غماز، تونیک غیرمعمول) روی چند seed مختلف ۱۰/۱۰ شد.
- گام دقیق مقام سیکاه طبق زنجیرهٔ اجناس اصلاح شد (درجهٔ ۵ = ۷۰۰ سنت؛
  نسخهٔ ۶۵۰ مربوط به خاندان حزام/عراق است و به‌عنوان گزینه ثبت شده).

### 🎼 سولفژ دقیق دوگانه + نظام مطلق درجات شرقی

ابزار برای هر نت، **دو نام** گزارش می‌کند:

1. **نام مطلق در نظام درجات شرقی** (راست، زیرکوله، دوگاه، کردی، سیکاه،
   بوسلیک، جهارکاه، حجاز، نوا، حصار، حسینی، عجم، اوج، ماهور، کردان، محیر،
   سنبله و…) — همان نظامی که در آموزش تلاوت به‌کار می‌رود («بیاتی از
   دوگاه»، «صبای از دوگاه» و…). این نام‌گذاری سیار است: هر فرکانسی که قاری
   برای تونیک بخواند، بقیهٔ درجات نسبت به همان تونیک نام‌گذاری می‌شوند.
2. **سولفژ سیار** (درجهٔ ۱ تا ۷ نسبت به تونیک مقام + رجیستر قرار/جواب).

به‌علاوه:

- **جدول کامل درجات مقام تشخیصی** در خروجی (`maqam_degree_table`): هر ۸
  درجه با نام مطلق، فاصلهٔ سنتی و فرکانس مورد انتظار نسبت به تونیک واقعی
  همین تلاوت.
- **گزارش «درجاتِ خوانده‌شده»** (`recitation_degrees`): مقام از کدام درجه
  آغاز شده، روی کدام درجه می‌نشیند (وقف)، و هر درجه چند درصد از تلاوت را
  اشغال کرده.
- **تشخیص مستقل از درجهٔ آغاز**: قاری هر جا شروع کند (تونیک، غماز، اوج)،
  تونیک واقعی و جایگاه دقیق آن (تا نیم‌سنت، با پالایش زیرشبکه‌ای
  `refine_tonic_hz`) مشخص می‌شود.
- **پرچم نت‌های خارج از مقام**: هر نت با تلورانس ۴۰ سنت با جدول درجات
  مقام تطبیق داده می‌شود (`in_maqam`).
- **ساختار نزولی**: مقاماتی که سرازیری متفاوتی دارند (مثل نهاوند که درجهٔ
  ۷ نزولی‌اش به عجم/نیم‌بمل می‌رود) با الگوی جداگانه در تشخیص لحاظ می‌شوند
  (`scale_form: ascending/descending`).
- اصلاح ساختار مقامات بر پایه MaqamWorld: صبا (چهارم نیم‌بمل‌گرفته در ۴۰۰
  سنت + پرش سه‌ودیما به حسینی — امضای اصلی صبا) و سیکاه (درجهٔ ۵ = عجم در
  ۶۵۰ سنت).

### 🎯 سیاست دقت: همیشه حداکثر دقت، صرف‌نظر از طول فایل

این ابزار **هرگز** به‌خاطر سرعت از کیفیت تحلیل کم نمی‌کند — حتی برای فایل‌های
۳۰-۶۰ دقیقه‌ای. تنظیمات Praat همیشه `very_accurate=True` با پاس دوگانه است.

مشکل مهندسی واقعی برای فایل‌های خیلی طولانی «حافظه» است، نه «دقت»: بارگذاری
یک‌جای کل فایل در حافظه می‌تواند باعث اتمام حافظه (OOM) شود. راه‌حل این
پروژه **پردازش پنجره‌ای** است (`extract_pitch_contour_max_accuracy` در
`pitch_engine.py`): فایل در پنجره‌های ۲ دقیقه‌ای با هم‌پوشانی کوچک خوانده
می‌شود، هر پنجره با همان تنظیمات حداکثر دقت پردازش می‌شود، و نتایج بدون از
دست دادن کیفیت به هم متصل می‌شوند. در آزمایش داخلی:

| طول فایل | زمان پردازش | پیک حافظه |
|---|---|---|
| ۱۰ دقیقه | ~۱۴ ثانیه | ~۲۰۰ مگابایت |
| ۳۰ دقیقه | ~۲۳ ثانیه (فقط pitch) | ~۲۳۰ مگابایت |
| ۶۰ دقیقه (بدون پنجره‌بندی) | ❌ خطای Out-Of-Memory | — |

برای فایل‌های طولانی، پیشرفت پردازش به‌صورت زنده در ترمینال چاپ می‌شود
(`قابل غیرفعال‌سازی با --quiet-progress`).

### 🕐 تایم‌لاین تغییر مقام (برای فایل‌های طولانی، ۸+ دقیقه)

برای تلاوت‌های طولانی، این ابزار دیگر فقط «یک مقام برای کل فایل» گزارش
نمی‌دهد. فایل به‌صورت خودکار به پنجره‌های ۴۵ ثانیه‌ای تقسیم می‌شود، مقام هر
پنجره جداگانه تشخیص داده می‌شود، و **نقاط گذار بین مقام‌ها** (مثلاً از بیات
به حجاز در ثانیه فلان) به‌صورت زمان‌بندی‌شده گزارش و روی ملوگراف رسم می‌شود.
این ویژگی در گزارش JSON زیر کلید `maqam_timeline` و در گزارش متنی زیر عنوان
«تایم‌لاین تغییر مقام» ظاهر می‌شود؛ برای فایل‌های کوتاه‌تر از ۸ دقیقه این
بخش خالی می‌ماند (چون یک مقام واحد برای کل فایل کافی و معنادار است).

**⚠️ محدودیت صادقانه:** تشخیص مقام یک برآورد آماری از روی توزیع نت‌هاست
(مثل الگوریتم کروم‌هنسل-اشموکلر در موسیقی غربی)، نه تحلیل کامل «سیر ملودیک».

## ۳. `piano_visualizer.py` — نمایش زنده نت روی پیانو 🎹

یک کلاویه ۸۸-کلیدی رسم می‌کند و هم‌زمان با پخش صدا (یا میکروفون)، نت فعلی
را روی کلاویه هایلایت می‌کند — شبیه "پیانوی شبح" در نرم‌افزارهای آموزشی.

```bash
# پخش فایل صوتی + نمایش هم‌زمان پیانو (نیازمند GUI/بلندگو)
python3 piano_visualizer.py --file recitation.mp3

# ورودی زنده میکروفون
python3 piano_visualizer.py --mic

# 🎬 صادرات ویدیو (mp4) — کار می‌کند حتی روی سرور بدون نمایشگر/صدا
python3 piano_visualizer.py --file recitation.mp3 --export-video --output piano_video.mp4
```

**ویژگی رنگ‌بندی کلید:**
- 🟢 سبز: نت دقیقاً کوک است (کمتر از ۱۵ سنت انحراف)
- 🟠 نارنجی: انحراف متوسط (۱۵ تا ۳۵ سنت)
- 🔴 قرمز: انحراف زیاد یا **ربع‌پرده** (نزدیک ۵۰ سنت) — این دقیقاً حالتی
  است که برای نت‌های خاص مقام‌های عربی (مثل سیکاه) طبیعی و مورد انتظار است.

> حالت پنجرهٔ زندهٔ تعاملی (`--file` یا `--mic` بدون `--export-video`)
> نیازمند محیط دسکتاپ با GUI و دستگاه صوتی (میکروفون/بلندگو) است و در محیط
> سرور بدون صفحه‌نمایش (headless) اجرا نمی‌شود.

### 🎬 صادرات ویدیو — دو حالت نمایش برای هر فایل آپلودی

طبق نیاز کاربر، برای هر فایل آپلودشده **هر دو** حالت زیر در دسترس است:

1. **گزارش استاتیک** (خروجی `quran_maqam_analyzer.py`) — ملوگراف PNG + گزارش متنی/JSON.
2. **ویدیوی MP4** (خروجی `--export-video`) — کلاویه پیانو که هم‌زمان با
   پخش صدای اصلی، نت جاری را هایلایت می‌کند؛ در هر مرورگر یا پخش‌کننده
   رسانه قابل پخش است.

مراحل داخلی `--export-video`:
1. استخراج پرده صدا با **همان تنظیمات حداکثر دقت** (پردازش پنجره‌ای برای
   فایل طولانی، طبق سیاست دقت پروژه — نه یک نسخهٔ سبک‌شده برای ویدیو).
2. رندر فریم‌به‌فریم کلاویه پیانو (پیش‌فرض ۱۲ فریم بر ثانیه، کافی برای
   همگام‌سازی بصری با گفتار/آواز انسانی) با `matplotlib.animation.FFMpegWriter`.
3. مالتی‌پلکس (mux) ویدیوی تولیدشده با فایل صوتی اصلی از طریق `ffmpeg`
   خط‌فرمان، برای هم‌گام‌سازی کامل صدا و تصویر.

نیازمند نصب سیستمی `ffmpeg` (`sudo apt-get install -y ffmpeg`).

## ۴. `compare_recitations.py` — مقایسه دقیق دو فراز 🔍

```bash
python3 compare_recitations.py reference.mp3 performance.mp3
python3 compare_recitations.py reference.mp3 performance.mp3 --output compare.json
```

فراز مرجع (مثلاً تلاوت یک قاری معروف) را با فراز دیگری (اجرای کاربر) از
سه بعد مقایسه می‌کند:

1. **شباهت ملودیک** (وزن ۵۵٪) — با DTW روی دنباله نت‌ها، به‌صورت *نسبی*
   (نرمال‌شده با میانه پرده صدای خودش) تا مستقل از زیر-و-بمی مطلق دو گوینده باشد.
2. **شباهت ریتمیک** (وزن ۳۰٪) — الگوی طول نسبی نت‌ها، مستقل از سرعت مطلق قرائت.
3. **شباهت بلندی صدا** (وزن ۱۵٪).

خروجی شامل امتیاز کلی، توصیه‌های بهبود، ریزترین انحرافات نت‌به‌نت، و یک
نمودار هم‌پوشانی دو ملوگراف + نمودار میله‌ای امتیازها.

**نتایج صحت‌سنجی داخلی** (تست‌شده روی صدای واقعی):
| سناریوی تست | شباهت ملودیک |
|---|---|
| فایل با خودش | ۱۰۰٪ |
| فایل + کمی pitch-shift (۰.۳ نیم‌پرده) | ۴۷٪* |
| فایل + بخش کاملاً متفاوت | ۲۷٪ |

*عدد پایین‌تر از انتظار در ردیف دوم به دلیل حساسیت ذاتی الگوریتم تفکیکِ
نت به نویز آرتیفکتی سیگنال تست است؛ روی صدای طبیعی انسان (نه سیگنال
مصنوعی) این اثر کمتر است. برای نتایج قابل‌اتکا، از فایل‌های با کیفیت
مناسب (بدون فشرده‌سازی شدید) استفاده کنید.

## ۵ و ۶. ابزارهای عمومی (غیر اختصاصی قرآن)

- `python/audio_analyzer.py` — تحلیل موسیقی عمومی با `librosa` (BPM، کلید،

## ۷. سرور بک‌اند + رابط وب کامل (`server/main.py`) 🌐

تب «تحلیل تلاوت قرآن (AI)» در `web/index.html` رابط کاربری کامل موتور
پایتونی است — همهٔ محاسبات سنگین (Praat، تشخیص مقام، DTW) در سرور اجرا
می‌شود، مرورگر فقط UI/آپلود/نمایش نتیجه است.

```bash
cd server
pip install -r requirements.txt
python3 main.py
# سپس در مرورگر باز کن: http://localhost:8080
```

این سرور یک اپ FastAPI است که **هم API و هم فایل‌های استاتیک وب را از یک
پورت (۸۰۸۰) سرو می‌کند** (برای پرهیز از مشکلات CORS). قابلیت‌ها:

| قابلیت | مسیر API | توضیح |
|---|---|---|
| آپلود فایل | `POST /api/upload` | فایل را ذخیره کرده و `job_id` برمی‌گرداند |
| تحلیل کامل | `POST /api/analyze/{job_id}` | گزارش + ملوگراف + تایم‌لاین مقام (async، پیشرفت زنده) |
| صادرات ویدیو | `POST /api/video/{job_id}` | ویدیوی پیانوی هم‌گام (mp4) |
| مقایسه دو فراز | `POST /api/compare` | با پارامترهای اختیاری برش زمانی (`ref_start`, `ref_end`, ...) |
| پیشرفت زنده | `WS /ws/job/{job_id}` | وب‌سوکت برای نوار پیشرفت لحظه‌به‌لحظه (برای فایل‌های طولانی) |
| پیانوی زنده میکروفون | `WS /ws/live-pitch` | صدای میکروفون مرورگر را استریم و با Praat واقعی تحلیل می‌کند |

**نکات معماری مهم:**
- تحلیل‌های طولانی (که می‌توانند دقیقه‌ها طول بکشند) در یک **ترد پس‌زمینه**
  اجرا می‌شوند تا event loop سرور مسدود نشود؛ کاربر از طریق وب‌سوکت
  پیشرفت واقعی (٪) را لحظه‌به‌لحظه می‌بیند — دقیقاً طبق سیاست «دقت، سپس
  اطلاع‌رسانی پیشرفت» که برای فایل‌های طولانی درخواست شده بود.
- «پیانوی زنده با میکروفون» در وب، برخلاف نسخهٔ پایتونی محلی
  (`piano_visualizer.py --mic`)، صدا را به‌صورت زنده به بک‌اند استریم
  می‌کند تا از همان دقت Praat (نه یک تخمین ساده‌شدهٔ جاوااسکریپتی) استفاده
  شود — با هزینهٔ کمی تأخیر شبکه.
- مقایسهٔ دو فراز از فیلدهای اختیاری بازهٔ زمانی (شروع/پایان به ثانیه)
  پشتیبانی می‌کند تا کاربر بتواند بخش دلخواه خودش را از فایل مرجع/کاربر
  به‌صورت دستی انتخاب کند (برش با `ffmpeg` در سرور انجام می‌شود).

> ⚠️ این سرور برای دمو/توسعه است (بدون احراز هویت/HTTPS/rate-limit)، پیش
> از استقرار در محیط عمومی (production) این موارد را اضافه کنید.

| امتیازدهی تمرین | زیرامتیاز **زینت/ویبرو** (پوشش ۴۵٪ + نرخ ۵–۷ هرتز + دامنهٔ ۳۰–۶۰ سنت) · **فیدبک فرازه‌به‌فرازهٔ قابل‌پخش** (کلیک = پخش همان فراز از صدا) · خروجی **CSV** تاریخچه · وزن‌های بازتنظیم‌شده |
| یادگیری سبک | **هموارسازی** آمارهای کم‌نمونه (α=۰٫۵) · **سه‌تایی‌های گذر** (top-12 در هر مقام) · **انسجام نمونه‌ها** (self_check) · پروفایل‌های demo از دیتاست آیه‌به‌آیهٔ عمومی بازسازی شدند |
| موتور ملودیک | **الگوی کشش خود کاربر** (۶ فاصلهٔ زمانی آخر نرمال‌شده) در اولویت پیشنهاد · واریانت «جملهٔ نیمه» روی **غماز** (ادامه‌پذیر) و «جملهٔ کامل» روی قرار |
| پیچ | **نوار ساکو-چیبا** در هم‌ترازی DTW (مقایسهٔ فرازهای بلند سریع‌تر و مهارشده) |
| پایداری سرور | پاک‌سازی خودکار jobهای >۲۴ ساعت · **بازیابی jobهای انجام‌شده** پس از ری‌استارت · `GET /api/health` |
| مربی زنده | هینت بالاتر/پایین‌تر فقط پس از **پایداری ~۱٫۳ ثانیه** (بدون چشمک‌زدن) · «نگه دار ✓» یک‌بار در هر رگه |
| وب | محدودیت‌های خام میکروفون (خاموشی AGC/NS/EC برای دقت Praat) · پیانوی **کلیک‌پذیر** · پخش ویبرو (LFO ۵٫۵Hz) در موتور ملودیک |

### 🎼 بازطراحی مقام‌ها و تب آموزش سولفژ (بر پایهٔ جدول کاربر)

- **۸ مقام مرجع «بر پایهٔ دو»** با نام نت‌های فارسی (نیم‌بمل = −۵۰ سنت): راست، صبا، نهاوند، عجم، حجاز، بیاتی، سه‌گاه، صبا زمزم — مستند در `docs/maqamat_degrees.md` و API `GET /api/maqamat`.
- **تشخیص کلی/اجمالی** (مستقل از ترتیب نت‌ها و مقاوم به پرش‌ها): بهاتاچاریای ریزبین + سنجش پوشش گام (set-fit) + تفکیک جفت‌های خلط‌شدنی با «درجه‌های ممیز» (راست/سه‌گاه/عجم و…) — در همهٔ نقاط سایت: تحلیل، تایم‌لاین، فرازها، پیانوی زنده (با ضدچشمک)، تمرین و موتور ملودیک.
- **تب «🎓 آموزش سولفژ»**: پخش جمله‌های سولفژ با انیمیشن بالا-پایین نت (نقطهٔ متحرک + سیلابس)، سه نوع تمرین (گام رونده، پرشی تصادفی، جنس‌به‌جنس)، تونیک پیش‌فرض از پروفایل صوتی، و حالت تمرین میکروفونی با رسم منحنی کاربر روی نت‌های هدف و امتیاز نت‌به‌نت.

**تست‌ها:** `python3 tests/test_engines.py` (۳۵ چک) + CI در `.github/workflows/ci.yml`.

**نکتهٔ صادقانه:** تمایز بیرون‌نمونه (hold-out) بین «قاری نمونه»های دیتاست عمومی روی آیه‌های کوتاه محدود است (فرازهای ۲–۸ ثانیه‌ای امضای کافی ندارند)؛ با تلاوت‌های طولانی‌تر (مثلاً یک جوانهٔ کامل) دقت تشخیص سبک به‌مراتب بالاتر می‌رود. سنجهٔ «انسجام نمونه‌ها» در هر پروفایل کیفیت دادهٔ ورودی را نشان می‌دهد.
