# 📱 همیار قاری — اپ کاملاً بومی اندروید (Kotlin)

تحلیلگر گسترهٔ صدای خواننده: **بالاترین و پایین‌ترین نتی که خوانده شده**،
گستره بر حسب نیم‌پرده/اکتاو، نمودار «ردِّ صدا»، جدول سهم نت‌ها، مکث‌ها و
گزارش قابل‌ذخیره — همه روی خود گوشی.

> **این اپ هیچ WebView، هیچ HTML، هیچ سرور و هیچ مجوز اینترنتی ندارد.**
> Kotlin خالص + API های خود اندروید (MediaCodec، AudioRecord، Canvas، MediaStore).
> برای اثبات: بعد از نصب، حالت هواپیما را روشن کنید؛ همه‌چیز کار می‌کند.

| | |
|---|---|
| بستهٔ نصبی | `release/hamyar-qari-1.1.4.apk` |
| نام بسته | `ir.hamyareqari.app` (مستقل — کنار «ردِّ صدا» نصب می‌شود) |

| زبان | Kotlin 2.4.21 · JVM target 1.8 |

## 🌿 شاخه‌ها

| شاخه | چیست |
|---|---|
| `main` | نسخهٔ وبِ مرجع (رابط HTML/سرور) |
| `MOBILE` | شاخهٔ موبایل/نمونهٔ اولیه |
| `android` | **شاخهٔ مادرِ اپ بومی Kotlin** — مستقل، کنار دو شاخهٔ بالا |

`android` عمداً **با هیچ شاخه‌ای مرج نمی‌شود**؛ تاریخِ خودش را دارد و فقط
جلو می‌رود (fast-forward). ساخت/هم‌گام‌سازی‌اش:

```bash
bash android-qari/tools/sync_android_branch.sh --dry-run   # بررسی
bash android-qari/tools/sync_android_branch.sh             # ساخت یا هم‌گام‌سازی
```

اسکریپت هیچ merge و هیچ pull requestی نمی‌سازد، بازنویسیِ تاریخ را رد می‌کند
و حذف/force-push روی `android` را ممنوع می‌کند.


## 🎧 پخش‌کنندهٔ صوتی و زومِ روان

بالای نمودار یک پخش‌کنندهٔ صوتیِ ارتقایافته هست: دکمهٔ گرد طلایی با حلقهٔ پیشرفت،
موجِ واقعیِ فایل روی نوار زمان (با رنگ متفاوت برای بخش پخش‌شده)،
پرش ۱۰ ثانیه به عقب/جلو، زمان‌های فارسی، سرعت پخش (۰٫۵× تا ۱٫۵×)،
کلید «دنبال‌کردن» و بازگشت به ابتدا. حرکت نوار زمان با سرعت انتخاب‌شده هم‌گام است
و در پایان فایل، وضعیت پخش و نقطهٔ نمودار به انتها می‌رسند.

**زوم دیگر قفل نمی‌کند.** هندسهٔ منحنی یک‌بار در «فضای زمان» ساخته می‌شود
و هر فریم فقط بخشِ داخل کادر به پیکسل تبدیل می‌شود؛ کادر هم با پخش جلو
می‌رود، پس نقطهٔ طلایی بدون توقف به حرکت خودش ادامه می‌دهد.

اجرای تست‌ها (شبیه‌ساز MediaCodec و تستِ پیکسلیِ زوم، بدون گوشی):

```bash
bash android-qari/test/sim/run_tests.sh
```

## نصب

1. فایل `release/hamyar-qari-1.1.4.apk` (یا از بخش Releases) دانلود کنید.
2. روی گوشی بازش کنید؛ اگر پیام «نصب از منابع نامشخص» آمد، برای همین برنامه
   اجازه بدهید (این پیام برای هر اپی که از فروشگاه نیامده طبیعی است).
3. اگر نسخهٔ قبلی را دارید، همین فایل روی آن به‌روزرسانی می‌شود
   (کلید امضا: `keystore/hamyar-qari.jks`).

## بعد از نصب، همین اول این را بزنید

در تب «تحلیل فایل»، پایین صفحه دکمهٔ **«🔬 آزمون داخلی موتور روی همین گوشی»** هست.
یک اجرای مرجع مصنوعی (A3 سپس A4) همان‌جا ساخته می‌شود و از مسیر تحلیل واقعی
می‌گذرد. اگر نوشت **«✅ موتور تحلیل سالم است»** یعنی هستهٔ اپ روی گوشی شما
درست کار می‌کند و اعدادش را هم نشان می‌دهد.

## چه می‌کند؟

| قابلیت | توضیح |
|---|---|
| 🎯 بالاترین/پایین‌ترین نت | از میان نت‌هایی که واقعاً خوانده شده‌اند؛ جیغ و لغزشِ لحظه‌ای کنار گذاشته و جداگانه گزارش می‌شود |
| 📏 گستره | نیم‌پرده، پرده، اکتاو، سنت، ربع‌پرده، درصد از یک اکتاو + «مرکز صدا» |
| 🎼 نمودار ردِّ صدا | خطوط نت + منحنی خوانده‌شده + نقطهٔ نورانی؛ **لمس روی نمودار = پخش از همان لحظه** |
| 🎚 نوار گستره | نقطه‌های نیم‌پرده در اکتاوها؛ پایین‌ترین فیروزه‌ای و بالاترین طلایی |
| 📊 سهم نت‌ها | کدام نت چقدر و چند بار خوانده شده |
| 🫁 مکث‌ها | شمار سکوت‌های ≥۰٫۳ ثانیه و بلندترین‌شان |
| 🎙 اجرای زنده | نمایش لحظه‌ای نت + عقربهٔ کوک (سنت) + گسترهٔ زنده + ۱۲ ثانیه نمودار |
| ⏺ ضبط اختیاری | اگر «ضبط» را روشن کنید، صدا در حافظه می‌ماند و بعد تحلیل/ذخیره می‌شود؛ **اگر روشن نکنید هیچ صدایی ذخیره نمی‌شود** |
| 🎬 ویدیوی ردِّ صدا | ساخت MP4 روی گوشی با MediaCodec (H.264 + AAC) و ذخیره در گالری — ۵۴۰p یا ۷۲۰p |
| 🔍 زوم نمودار | زوم زمانی (⏱ ±) و زوم ارتفاع (↕ ±) و بازنشانی — مثل نسخهٔ وب |
| 🎚 کاهش نویز | دروازهٔ طیفی (STFT) برای کم‌کردن هیس و هم اتاق |
| 📐 درجه | گستره بر حسب «درجه» (اکتاو = ۸ درجه)، مثل قرارِ نسخهٔ وب |
| ▶ نمونهٔ آزمایشی | یک تلاوت ۳۸ ثانیه‌ای داخل خود اپ؛ بدون نیاز به فایل |
| ⏺ ضبط‌های جلسه | فهرست همهٔ ضبط‌ها با تحلیل/ذخیره/حذف هرکدام و «حذف همه» |
| 💾 خروجی | تصویر PNG، گزارش JSON، صدای WAV، **فایل اصلی**، ویدیوی MP4 + اشتراک‌گذاری |
| 🔒 آفلاین مطلق | نه اینترنت، نه سرور، نه حساب کاربری |

ورودی‌ها: هر چیزی که خودِ اندروید رمزگشایی می‌کند — `mp3، m4a/aac، wav، flac،
ogg/opus، amr، mp4، mkv، webm`. صدای ویدیو با `MediaCodec` جدا می‌شود.

## چطور کار می‌کند (و چرا قابل اعتماد است)

```
src/ir/hamyareqari/dsp/    هستهٔ تحلیل — بدون هیچ وابستگی به اندروید (روی JVM تست می‌شود)
  Signal.kt        دسترسی یکنواخت به نمونه‌ها (۱۶ بیتی، کم‌مصرف برای فایل بلند)
  Fft.kt           FFT پایه‑۲ + پنجرهٔ هَن + درون‌یابی سهمی قله
  Yin.kt           ردیاب f0 به روش YIN با همبستگی FFT، گام ۵ms، بازهٔ ۵۵–۱۲۰۰Hz
  Harmonics.kt     اصلاح «نردبان هارمونیک» + پالایش هر نت با برازش هارمونیک‌ها
  Segment.kt       تفکیک نت‌ها با هیسترزیس (۴۵/۷۲ سنت) + آمار و انتخاب نت واقعی
  Analyzer.kt      خط لولهٔ کامل + کیفیت + «موتور دوم» McLeod برای هم‌رأیی
  Wav.kt / Json.kt خواندن/نوشتن WAV و گزارش JSON
  Denoise.kt       کاهش نویز با دروازهٔ طیفی
  SelfTest.kt      آزمون داخلی روی گوشی

src/ir/hamyareqari/app/    لایهٔ اندروید (Kotlin + فریم‌ورک خالص، بدون AndroidX)
  MainActivity.kt  دو تب: تحلیل فایل، اجرای زنده
  ChartView.kt     نمودار Canvas (و همان کد برای خروجی PNG)
  RangeStripView   نوار گستره + عقربهٔ کوک
  AudioIo.kt       MediaCodec / AudioRecord / MediaPlayer + تبدیل نرخ جریانی
  VideoMaker.kt    ساخت MP4: Bitmap→YUV420→H.264 + PCM→AAC + MediaMuxer
  Persistence.kt   MediaStore (اندروید ۱۰+) و مسیر جایگزین (اندروید ۸–۹)
```

مراحل تحلیل:

1. **یکسان‌سازی ورودی** — مونو، ۲۲٬۰۵۰ هرتز، حذف DC، بالاگذر ۴۵ هرتز،
   نرمال‌سازی پیک به ۰٫۹. یعنی mp3 و wav و ویدیو نتیجهٔ یکسان می‌دهند.
2. **ردیابی f0** با YIN (تابع تفاضل با FFT، O(N log N) — اجرای روی گوشی ممکن).
3. **اصلاح نردبان هارمونیک** — برای هر ران صدادار، فرض‌های ¼×، ⅓×، ½×، ۱×،
   ۲×، ۳×، ۴× با «امتیاز هماهنگی هارمونیک» سنجیده می‌شوند. این کار خطای اکتاو،
   خطای هارمونیک سوم/چهارم و گم‌شدن فرکانس پایه را می‌گیرد.
4. **پالایش هر نت** — طیف در طول نت میانگین گرفته می‌شود، جای هر هارمونیک با
   درون‌یابی سهمی پیدا و f0 با کمترین مربعات روی همهٔ هارمونیک‌ها برازش می‌شود.
5. **تفکیک نت‌ها** با هیسترزیس و ادغام شکاف‌های کوتاه؛ برای هر نت شفافیت،
   پایداری (سنت) و لغزش گزارش می‌شود.
6. **آمار گستره** روی نت‌های «واقعی» (۲ بار یا ≥۰٫۳ ثانیه)، و گزارش خام جداگانه.

### اندازه‌گیری دقت (قابل تکرار)

```bash
cd android-qari
JAVA_HOME=... /path/to/java -cp kotlin-compiler.jar org.jetbrains.kotlin.cli.jvm.K2JVMCompiler \
  -no-reflect -jvm-target 1.8 -d /tmp/out src/ir/hamyareqari/dsp/*.kt tools/DspCheck.kt
java -cp /tmp/out:kotlin-stdlib.jar ir.hamyareqari.tools.DspCheck
```

یک اجرای مرجع (A3 → A4 و برگشت، ۱۴ نت، با ویبراتو و هارمونیک) در ۸ قالب سنجیده
می‌شود. نتیجهٔ آخرین اجرا:

| آزمون | بالاترین | پایین‌ترین | گستره | میانهٔ خطای کوک |
|---|---|---|---|---|
| مرجع ۲۲٬۰۵۰Hz | A4 | A3 | ۱۲٫۰۱ | ۱٫۰۵ سنت |
| نسخهٔ ۱۶٬۰۰۰Hz | A4 | A3 | ۱۲٫۰۱ | ۰٫۵۵ سنت |
| باند تلفنی ۸k | A4 | A3 | ۱۲٫۰۰ | ۰٫۵۱ سنت |
| کم‌صدا + نویز | A4 | A3 | ۱۲٫۰۱ | ۰٫۸۱ سنت |
| ۶۰ ثانیه سکوت در ابتدا | A4 | A3 | ۱۲٫۰۲ | ۱٫۰۴ سنت |
| نصف بلندی + قطبیت برعکس | A4 | A3 | ۱۲٫۰۱ | ۱٫۰۵ سنت |
| یک نت تنها C4 | C4 | C4 | ۰٫۰۰ | ۱٫۰۱ سنت |
| نت بم ۱۱۰Hz | A2 | A2 | ۰٫۰۰ | ۰٫۲۹ سنت |

روی تن خالص، خطا حدود **۰٫۱ سنت** است.

### تطابق با نتیجهٔ مرجع پروژه (روی فایل واقعی)

همان فایل نمونهٔ خود پروژه (`web/demo_bayati.wav`، تلاوت ۳۸٫۲۵ ثانیه‌ای) از مسیر
واقعی اپ گذشت و نتیجه با اعداد مستندشدهٔ نسخهٔ وب یکی درآمد:

| | مرجع پروژه (وب) | اپ بومی (Kotlin) |
|---|---|---|
| بالاترین نت | A4 · ۴۴۰٫۴۱Hz | A4 · ۴۳۹٫۷۸Hz |
| پایین‌ترین نت | A3 · ۲۲۰٫۱۰Hz | A3 · ۲۱۹٫۸۵Hz |
| گستره | ۱۲٫۰۱ نیم‌پرده | ۱۲٫۰۰ نیم‌پرده |
| تعداد نت | ۴۵ | ۴۵ |
| طول | ۳۸٫۲۵ ثانیه | ۳۸٫۲۵ ثانیه |

یعنی دو پیاده‌سازی مستقل (JavaScript و Kotlin) روی دادهٔ واقعی به یک جواب
می‌رسند. زمان تحلیل: ۱٫۳ ثانیه برای ۳۸ ثانیه صدا.

## ساخت دوباره از کد

بدون Gradle و بدون Android Studio (پس بدون دانلود چند صد مگابایتی):

```bash
bash android-qari/tools/fetch_toolchain.sh        # JDK + aapt2 + android.jar + d8 + kotlinc
ANDROID_TOOLS=/tmp/android bash android-qari/build_apk.sh
# خروجی: release/hamyar-qari-1.0.0.apk
```

ابزارها از npm و PyPI می‌آیند (نه از سرویس‌های تحریمی) و در `/tmp/android`
می‌نشینند؛ هیچ فایل باینری سنگینی داخل مخزن نمی‌ماند.

نسخهٔ بعدی:

```bash
VERSION_NAME=1.1.4 VERSION_CODE=6 bash android-qari/build_apk.sh
```

> ⚠️ برای به‌روزرسانی روی نسخهٔ نصب‌شده، باید همان کلید امضا بماند:
> `keystore/hamyar-qari.jks` (رمز `hamyarqari`). اگر این فایل را پاک کنید،
> کاربران باید اپ را حذف و دوباره نصب کنند.

## نکات صادقانه

- **رابط کاربری روی دستگاه واقعی اجرا نشده است.** هستهٔ تحلیل روی کامپیوتر با
  ۸ سناریو سنجیده شده، ولی صفحه‌ها، ضبط زنده و ذخیره‌سازی فقط از نظر کد
  بازبینی شده‌اند. دکمهٔ «آزمون داخلی موتور» برای همین گذاشته شده که با یک
  کلیک سلامت موتور را روی گوشی خودتان ببینید. اگر جایی خطا دید، بگویید تا
  دقیقاً همان را درست کنم.
- اپ عمداً **بدون مجوز اینترنت** ساخته شده؛ پس هیچ‌چیز نمی‌تواند جایی فرستاده شود.
- «بالاترین/پایین‌ترین نت» از نت‌های واقعاً خوانده‌شده گرفته می‌شود، نه از تک‌فریم‌ها.
- فایل‌های بلندتر از ۴۰ دقیقه فقط ۴۰ دقیقهٔ اول تحلیل می‌شوند (برای حافظه).
- پخش نمونه برای فایل‌های بیش از ۱۵ دقیقه خاموش است (نمودار و اعداد دست‌نخورده‌اند).
- تبدیل نرخ نمونهٔ رمزگشا با درون‌یابی خطی و بدون فیلتر ضدآلیاسینگ است؛ چون
  آلیاس در باند ۲–۱۱ کیلوهرتز می‌افتد، روی تشخیص f0 اثری ندارد.
- اپ برای یک کاربر طراحی شده؛ در حین تحلیل، رابط منتظر می‌ماند (تحلیل در
  ترد پس‌زمینه با نوار پیشرفت انجام می‌شود).
- **ویدیو**: کدگذار H.264 در حالت ByteBuffer (تبدیل ARGB→YUV420 در کد) استفاده
  می‌شود؛ روی همهٔ گوشی‌های اندروید ۸+ باید موجود باشد، ولی این مسیر روی
  دستگاه واقعی آزموده نشده. اگر دستگاه کدگذار AAC نداشت، ویدیو بی‌صدا ساخته
  می‌شود و همان را هم پیام می‌دهد. ۷۲۰p چند برابر ۵۴۰p طول می‌کشد.
- کاهش نویز برای فایل‌های تا ۲۵ دقیقه فعال است (بالاتر از آن، بی‌صدا و با
  هشدار، نادیده گرفته می‌شود).
- زوم نمودار در لحظهٔ جاری متمرکز می‌شود؛ اگر پخش متوقف باشد، وسط اجرا.
